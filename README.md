## 파일 규칙

### 파일 이름

`일자_문제이름.py` 형식을 사용한다. 유형은 폴더로 구분하므로 파일 이름에는 넣지 않는다.

```
01_hash/27_number_pair.py   # 27일차에 푼 「숫자 짝꿍」
```

### 파일 내용

2026-08-31부터의 하루 한 문제 풀이는 **2단 구성**으로 쓴다. 최적화된 코드만 남기면
어디서 막혔고 무엇을 왜 고쳤는지가 사라지는데, 복습할 때 필요한 것은 정답이 아니라
그 차이이기 때문이다.

```python
# [날짜]
# 문제 이름 (Lv.n)
# 문제 링크


# --------------------------------------------------------------------------
# 1. 나의 풀이
# --------------------------------------------------------------------------
def solution(...):
    """내가 쓴 그대로 둔다. 통과한 버전이면 사후에 다듬지 않는다."""


# --- 피드백 과정 ---
#
# 접근이 어디서 나왔는지 · 무엇에 막혔는지 · 어떤 반례에서 갈렸는지.


# --------------------------------------------------------------------------
# 2. 최적화된 버전
# --------------------------------------------------------------------------
def solution(...):
    """요약 한 줄 + 핵심 아이디어."""


# --- 설명 ---
#
# 왜 그렇게 고쳤는지 · 시간/공간 복잡도 · 짧지만 안 되는 대안과 그 이유.
#
# 다시 만나면: 한 줄.
```

두 함수는 **같은 이름을 그대로 쓴다.** 아래쪽 정의가 위쪽을 덮으므로 파일을 그대로
실행하면 최적화된 버전이 돈다 — 최종 정답이 무엇인지 따로 표시할 필요가 없다.

「나의 풀이」가 이미 최적화된 형태여서 고칠 것이 없으면 2단을 생략하고 「설명」만 붙인다.

Docstring은 (1) 요약 한 줄 → (2) 알고리즘 설명 → (3) 인자 설명 → (4) 반환값 설명으로 구성한다.
인자와 반환값이 문제 설명에서 자명한 짧은 문제에서는 (1)~(2)만 써도 된다.

```python
def calculate_area(radius):
    """원의 넓이를 계산하여 반환한다.          # (1) 요약 한 줄

    반지름 값을 받아 수학 공식을 적용해 넓이를 구한다.  # (2) 상세 설명 (선택)

    Args:                                      # (3) 인자 설명
        radius (float): 원의 반지름 (양수여야 한다).

    Returns:                                   # (4) 반환값 설명
        float: 계산된 원의 넓이.
    """
    import math
    return math.pi * (radius ** 2)
```

### 주석

코드를 읽으면 알 수 있는 내용 대신, **그 방식을 선택한 이유**를 남긴다.

```python
def solution(priorities: list[int], location: int) -> int:
    # 나쁜 주석: "큐에 데이터를 넣는다"        (코드를 읽으면 알 수 있는 내용)
    # 좋은 주석: "인덱스 관리를 위해 enumerate로 (우선순위, 위치) 튜플 생성"
```

### 풀이 메모

막혔던 지점·오류 원인·손으로 돌려본 과정처럼 **그 문제를 풀며 겪은 것**을 남긴다.
별도 파일로 분리하지 않고 그 코드 바로 아래 주석으로 두는데, 메모가 그 코드에만
해당하는 시행착오 기록이라 떨어뜨리면 문맥이 끊기기 때문이다.

2단 구성에서는 메모가 두 곳으로 나뉜다.

| 블록 | 넣을 것 |
| --- | --- |
| `--- 피드백 과정 ---` | 접근, 막힌 지점, 갈린 반례, 문법·개념 착오 |
| `--- 설명 ---` | 고친 이유, 시간·공간 복잡도, 더 나은 표현, 짧지만 안 되는 대안과 그 이유, 「다시 만나면」 한 줄 |

「다시 만나면」은 **같은 문제가 아니라 같은 유형을 다시 만났을 때 떠올릴 한 줄**이다.
문제 이름이 아니라 판단 기준을 적는다. 코드를 고쳐도 이 기록은 지우지 않는다.
